## 2. 通用实施与审查契约

每个批次严格使用以下闭环：

1. 运行该批现有定向测试，确认基线。
2. 为每个缺陷加入稳定复现错误行为的失败测试；测试在实现修改前必须因目标缺陷失败。
3. 实施满足测试的最小修复，不扩大公共 API 或重构范围。
4. 运行格式检查、静态检查、定向测试和子系统回归测试。
5. 对本批 diff 执行高强度代码审查，重点检查正确性、并发、失败原子性、安全边界和测试缺口。
6. 逐条回到代码和可执行路径核验审查发现。只修复确认成立且由本批改动引入或暴露的问题；对误报记录核验依据，不做迎合性改动。
7. 每个确认发现先补充或收紧失败测试，再修复并重跑定向测试与回归测试。
8. 重复“审查—核验—修复”直到本批没有确认成立的审查发现，再创建独立提交。

若发现必须改变本规格的外部行为、数据格式或安全边界，应停止该批并先更新规格，不得在代码中静默扩展范围。

## 3. 批次 1：语义搜索可靠性与确定性

### 3.1 #8 单毒丸块无限重试

`SemanticEngine` 在整批嵌入失败且没有幸存块时，用固定、已知可编码的健康文本执行一次不入库的 canary 探测：

- canary 也失败：判定为后端或环境级故障，不消耗内容块失败额度，保留队列并返回原始错误供 worker 延迟重试。
- canary 成功：判定失败与内容相关，为失败块记录次数；达到现有上限的块进入现有隔离路径，未达到上限的块继续重试。
- 多块拆分后有幸存者时，保留现有“成功块入库、失败块计数”语义，不额外执行 canary。

canary 不写入 `embedding_chunks`、`embedding_vec` 或待办表。测试覆盖单毒丸最终耗尽额度、全局后端故障不烧额度、混合健康/毒丸批次仍能推进。

### 3.2 #9 粘滞取消状态

把永久布尔状态改为可失效的工作代次/取消票据：

- 每个后台索引工作在进入耗时操作前取得当前工作代次票据。
- 取消使该代票据失效；持有旧票据的下载、分词和嵌入工作应尽快终止。
- 后续后台工作取得新票据，无须把同一个原子布尔值从 `true` 写回 `false`，避免旧工作被重新放行。
- `is_query == true` 的交互式查询不受后台索引取消影响，只受自身请求生命周期或后端切换影响。
- 现有 generation 继续拒绝后端切换后的陈旧结果；它与停止工作的取消票据职责分离。

测试覆盖取消中的旧后台工作、新后台工作可恢复、取消后前台查询仍调用后端，以及旧代结果不能写入新索引。

### 3.3 #13 HTTP 嵌入请求不可取消

HTTP 嵌入后端接受与本次后台工作关联的可等待取消信号，用 `tokio::select!` 在 HTTP 响应和取消间竞争。取消分支丢弃请求 future 并返回明确的 `AppError::Cancelled`，而不是等待 60 秒超时。

它须与本地后端共用第 3.2 节票据语义，交互式查询不能继承已取消的后台票据。测试使用本地阻塞 HTTP 服务，验证取消在短超时内返回、普通响应不受影响、后端切换不再等待远端超时。

### 3.4 #15 BGE 截断保留 `[SEP]`

token 数超过 `MAX_SEQUENCE_LEN` 时，保留开头 `[CLS]` 和结尾 `[SEP]`：截断内容 token 后，把最后位置设为 tokenizer 实际使用的 SEP token id。未超限输入不变，最大长度仍为 512，不改变 padding 和 attention mask。

测试覆盖临界长度、超长输入、末 token 为 SEP、首 token 为 CLS，以及未超限编码不被改写。

### 3.5 #16 RRF 稳定排序

融合得分使用实际分数类型的总序比较按分数降序排列；得分完全相同时按稳定会话标识升序决胜。不得依赖 `HashMap` 迭代顺序或展示标题等可变字段。

测试以不同插入顺序构造相同分数集合，多次执行并断言顺序一致。

## 4. 批次 2：Windows 路径安全与本地持久化

### 4.1 #2 Windows 短路径与前缀边界

路径校验先做词法规范化，再对“最长已存在祖先”执行 Windows 规范路径解析/长路径展开，最后把尚不存在的尾部组件逐段安全拼回。这样既识别 `PROGRA~1`、`APPDAT~1` 等 8.3 别名，也允许校验尚未创建的目标文件。

所有“位于某目录下”判断改为组件边界比较或等价的 `Path::starts_with`，不得使用裸字符串前缀。`C:\Temp` 只能匹配自身及子项，不能匹配 `C:\Temporary`、`C:\Temp_Evil`。Windows 比较大小写不敏感，并统一处理分隔符、尾分隔符和 `\?\` 前缀。

若已有祖先无法规范化，校验应失败关闭；不得退回仅按原始字符串放行。Windows 测试覆盖 8.3 别名（系统支持时）、相邻前缀目录、不存在尾路径和允许的真实临时目录；不支持 8.3 的环境应明确跳过对应用例。

### 4.2 #18 备份恢复倒灌

为设置持久化引入明确备份策略：普通保存先把已验证的当前主文件轮换为 `.bak`；从 `.bak` 自愈时使用“保留现有备份”策略，绝不把已知损坏的主文件复制到 `.bak`。

自愈仍采用临时文件加原子替换写回主文件。若写回失败，原 `.bak` 必须可解析且内容不变。测试覆盖损坏主文件恢复、恢复写回失败、再次启动仍可恢复，以及普通保存仍保留上一版有效配置。

### 4.3 #19 连接级 PRAGMA

把 `journal_mode = WAL`、`synchronous = NORMAL`、`temp_store = MEMORY` 配置到 `SqliteConnectOptions`，确保池中新建的每条连接继承相同策略。删除建池后仅对随机签出连接执行的等价 PRAGMA。

测试同时签出多条连接，分别查询 `PRAGMA synchronous` 与 `PRAGMA temp_store`；所有连接须返回预期值。WAL 也要验证，但不能代替连接级断言。

### 4.4 #24 临时文件清理竞态

`cleanup_stale_temporaries` 只删除设置存储生成且最后修改时间早于 5 分钟阈值的临时文件。新文件、修改时间无法读取的文件、名称不属于设置临时文件命名空间的文件均保留。时间比较使用容错逻辑，避免时钟回拨误删活动文件。

测试覆盖新旧临时文件、相似名称文件、未来时间戳和元数据读取失败路径。

## 5. 批次 3：导入与用户脚本同步完整性

### 5.1 #25 保留纯思考 DeepSeek 消息

DeepSeek 导出节点含 `THINK` 片段但没有 `REQUEST` 或 `RESPONSE` 正文时，规范化为 `assistant` 消息并保留 `metadata.thinking`；正文允许为空字符串。完全没有用户、助手或思考内容的工具/空节点仍跳过。

现有含正文消息的角色判定和 metadata 格式不变。测试覆盖纯 THINK、THINK+RESPONSE、空节点，并确认纯思考消息的时间戳和节点关联元数据保留。

### 5.2 #26 导入请求分批

用户脚本不再把所有详情结果放入一次 `/sessions/import` 请求。批次生成器同时限制：

- 会话条目数量，避免大量小会话造成长任务和内存峰值；
- 用 `TextEncoder` 计算的完整 JSON 请求体 UTF-8 字节数，确保严格低于后端 20 MiB 限制并预留固定余量。

每批单独发送并汇总 `imported`、`skipped`、`sessions` 和 `failed`，保持 `fetchDetailsAndPush` 返回结构。单个会话连同 envelope 超过安全上限时，不发送必然失败的请求；将它加入失败结果和持久重试队列，并继续其余会话。批请求失败只影响该批，不撤销已成功批次。

测试覆盖按数量切分、按多字节 UTF-8 大小切分、单会话超限、第二批失败后的部分成功统计，以及现有重试次数契约。

### 5.3 #27 持久失败重试队列与游标

按平台持久化详情抓取/导入失败队列，队列键至少包含稳定会话 id，并保存最后已知更新时间、失败阶段和尝试次数。每轮候选是“正常增量候选 + 该平台重试队列”的去重并集；重试项不受 `last_updated_at` 过滤。

只有完成详情抓取并被后端确认导入或明确跳过的会话才从重试队列移除，并参与成功游标推进。失败项立即写入队列；页面刷新后仍会重试。各平台队列和游标隔离。成功批次可推进游标，失败项依靠队列继续被选择，避免永久坏会话阻塞后续增量。

持久化更新应在每批结果后进行。测试覆盖失败后游标推进、下一轮越过游标仍重试、成功后移除、刷新后恢复、平台隔离和候选去重。

## 6. 批次 4：前端安全、响应性与分页恢复

### 6.1 #28 Mermaid SVG 消毒

把 DOMPurify 作为应用的直接精确版本依赖固定为当前锁文件已使用的 `3.4.14`。新增单一共享 `sanitizeMermaidSvg` 边界，应用内和导出渲染在写入 `innerHTML` 前均调用它。

配置采用 SVG profile，显式禁止 `script`、`foreignObject`、事件属性和危险 URL 协议，同时保留 Mermaid 正常布局需要的 SVG、样式和引用属性。禁止两个路径复制不同配置。

测试向 Mermaid 输出注入脚本标签、事件属性、危险链接和 `foreignObject`，验证两条路径均移除危险内容；正常流程图的节点、边、文字和样式仍可渲染。

### 6.2 #30 导出文档分帧渲染

`ExportDocument` 不再在一个 computed 求值中同步渲染全部消息。改为可取消的分帧流水线：按小批量或单帧时间预算调用 `renderMarkdown`，每帧通过 `requestAnimationFrame` 让出主线程，并以渲染代次丢弃 props 变化后的旧结果。

组件暴露 `whenReady()`（或等价 ready promise）作为导出屏障。PDF、图片和 Mermaid 后处理只能在本代全部 Markdown 提交、Vue DOM 更新及 Mermaid 渲染完成后继续。空会话立即 ready；卸载时取消待处理帧并结束旧代，不允许导出半成品。

测试使用可控 rAF 验证大消息集跨帧处理、输入变化取消旧代、ready 只在最终 DOM 与 Mermaid 完成后解决，以及导出不会捕获中间状态。

### 6.3 #31 `loadMore` 失败后页码不跳跃

`loadMore` 先计算候选页 `page + 1`，用候选页请求；只有请求成功且结果属于当前 generation 时才提交页码。失败、取消或陈旧响应均保持当前页，使下次重试同一页。

加载期间继续禁止重复请求。测试覆盖失败后重试同页、成功后推进、过滤变化使旧响应作废，以及连续点击不会重复追加。

## 7. 批次 5：MCP 数据目录迁移一致性

桌面端完成迁移并确认新数据库可用后，在旧数据目录原子发布固定名称的迁移标记。标记经“同目录临时文件写入—flush—rename”生成，包含格式版本、迁移时间和新目录提示；MCP 不信任其中路径去自动打开数据库。

MCP stdio 的所有只读入口在每次查询或资源读取前执行统一 guard：

- 标记不存在：继续使用当前只读池。
- 标记存在且格式有效：拒绝查询，返回明确的“数据目录已迁移，请重启 MCP”错误。
- 标记存在但格式损坏：失败关闭，要求重启/检查，不继续返回旧数据。

本轮不实现 MCP 运行时换池、跨进程热重连或自动追随标记路径；重启后由现有启动路径从设置加载正确目录，避免引入第二套服务装配和路径信任边界。

迁移失败时不得发布标记；标记发布失败则目录迁移命令返回错误，不能宣称 MCP 一致性已建立。测试以独立 service/池模拟桌面和 MCP，覆盖迁移前可查、迁移后旧 MCP 拒绝、重启后新目录可查、失败迁移无标记、损坏标记失败关闭，以及全部 MCP 入口共用 guard。

## 8. 数据兼容性与错误处理

- 不进行数据库 schema 版本升级；数据库变化限于连接选项和运行时行为。
- 设置文件格式兼容，仅改变备份轮换时机。
- 用户脚本重试状态使用独立、带版本的平台命名空间；损坏状态回退为空队列，不影响已有游标读取。
- MCP 迁移标记是本地协调文件，不改变 MCP 工具 schema；错误通过现有 MCP 错误通道返回。
- 取消、超限、消毒和迁移标记错误须记录足够上下文，但不得记录会话正文、密钥或不必要的用户数据。

### 9.2 最终全量门禁

5 批全部结束后，从仓库根目录执行：

```text
node --check userscript/dist/ai-chat-memory.user.js
node --test userscript/tests/capture.test.mjs
cd app && npm run build && npm test
cd app/src-tauri && cargo fmt --check
cd app/src-tauri && cargo clippy --all-targets --all-features -- -D warnings
cd app/src-tauri && cargo test --all-features
```

只有命令全部以退出码 0 完成，且最终高强度审查没有确认成立的遗留发现，才能声明完成。若环境原因导致某项无法执行，须准确报告未验证项及原因，不能用其他检查替代为“已通过”。
